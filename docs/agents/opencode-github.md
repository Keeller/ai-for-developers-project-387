# OpenCode в GitHub Actions

Интерактивный агент настроен в `.github/workflows/opencode.yml`. Он читает
корневой `AGENTS.md` и отвечает в GitHub от имени приложения OpenCode Agent.

## Как запускается workflow

- `issue_comment` с `types: [created]` запускает workflow после создания
  комментария в issue или обсуждении pull request.
- `pull_request_review_comment` с `types: [created]` запускает workflow после
  создания комментария к строке в diff.
- Условие job пропускает работу дальше, только если комментарий оставил человек
  с ролью `OWNER`, `MEMBER` или `COLLABORATOR`, а его текст равен `/oc` либо
  начинается с `/oc `.
- События от любых bot-аккаунтов и отдельно от `opencode-agent[bot]`
  отбрасываются до запуска runner, поэтому ответ приложения не создаёт петлю.
- Параметр `mentions: /oc` передаёт единственную действующую команду самому
  OpenCode Action. Широкая команда `/opencode` намеренно отключена.

Редактирование и удаление старых комментариев агент не запускают.

## Права и учётные данные

Workflow получает только `id-token: write`. OIDC-токен обменивается на токен
установленного GitHub App, поэтому токен раннера не сохраняется в рабочей копии:
`actions/checkout` использует `persist-credentials: false`.

Модель `ollama-cloud/kimi-k2.7-code` работает через Ollama Cloud. Интерактивный
workflow явно использует агент `build`, потому что команда доверенного участника
может запросить изменение кода. Настройки провайдера лежат в корневом
`opencode.jsonc`, а ключ передаётся только через секрет репозитория
`OLLAMA_API_KEY`. Значение секрета никогда не записывается в файлы или историю
Git. Публикация сессии отключена параметром `share: false`.

## Ручная проверка

1. Создать issue с описанием задачи.
2. От имени владельца или участника с доступом на запись добавить комментарий
   `/oc explain this issue`.
3. Открыть **Actions → OpenCode agent** и дождаться завершения запуска.
4. Убедиться, что OpenCode Agent ответил в issue.

Время выполнения и журнал агента доступны в шаге **Run OpenCode** выбранного
запуска.

## Автоматический triage новых issue

Workflow `.github/workflows/opencode-triage.yml` запускается только при создании
новой issue (`issues` с `types: [opened]`). Поскольку событие не содержит команды
из комментария, инструкция агенту целиком задана параметром `prompt`.

Автотриаж запускается только для issue, созданных человеком с ролью `OWNER`,
`MEMBER` или `COLLABORATOR`; bot-аккаунты и OpenCode App отсекаются условием job.
Для анализа используется read-only агент `plan`: в `opencode.jsonc` ему явно
запрещены изменение файлов, shell-команды и запуск субагентов через `task`.

Агент изучает пользовательскую жалобу и публичный репозиторий, затем отвечает
по-русски: фиксирует вероятную причину, затронутые области и файлы, путь
исправления, тесты и критерии приёмки. Автотриаж не изменяет код, не создаёт
ветки или pull request и не закрывает issue.

## Автоматическое ревью pull request

Workflow `.github/workflows/opencode-review.yml` запускается для событий
`opened`, `synchronize`, `reopened` и `ready_for_review` у недрафтовых pull
request из этого же репозитория. Pull request из fork остаётся на ручном ревью:
GitHub принудительно урезает его `GITHUB_TOKEN` до read-only, поэтому OpenCode не
смог бы опубликовать результат. Проектный `prompt` требует проверить постановку,
контракт, использование сгенерированного SDK, серверные правила, тесты, типы и
безопасность.

Для чтения кода и контекста используются права `contents: read`, `issues: read`
и токен раннера через `use_github_token: true`. Право `pull-requests: write`
нужно OpenCode Action для реакции и публикации результата в обсуждении PR;
без него GitHub отвечает `403 Resource not accessible by integration`. Агент
`plan` и репозиторная конфигурация запрещают изменения файлов и shell-команды;
запуск более привилегированных субагентов также запрещён. Workflow не получает
`contents: write` и не меняет код.

Workflow явно пропускает только авторов с `author_association` `OWNER`,
`MEMBER` или `COLLABORATOR`. После этого OpenCode выполняет собственную
проверку прав автора. Любые bot-аккаунты и OpenCode App отсекаются отдельно.
Pull request от остальных авторов остаются на ручном ревью.
