# Браузерные сквозные тест-кейсы

Кейсы выполняются Playwright в Chromium через собранный React-интерфейс и
реальный Fastify API с изолированной PostgreSQL. HTTP-запросы разрешены только
для подготовки данных; проверяемое поведение выполняется и наблюдается в
браузере. Перед каждым кейсом база возвращается в исходное состояние.

## Типы событий

### TC-E2E-01 — Владелец создаёт и изменяет Тип события

1. Владелец открывает список Типов событий и переходит к созданию.
2. Вводит публичный ID, название, описание и длительность.
3. Сохраняет Тип события, затем открывает его редактирование.
4. Изменяет название, описание и длительность и сохраняет снова.

Ожидаемый результат: список показывает изменённые данные, а публичный ID
остаётся прежним и недоступен для редактирования.

### TC-E2E-02 — Публикация управляет видимостью для Гостя

1. Владелец скрывает опубликованный Тип события.
2. Гость открывает публичный список.
3. Владелец снова публикует Тип события.
4. Гость обновляет публичный список.

Ожидаемый результат: скрытый Тип события отсутствует у Гостя, а опубликованный
снова виден с названием, описанием и длительностью.

### TC-E2E-03 — Повторный публичный ID отклоняется

1. Владелец создаёт Тип события.
2. Через ту же форму пытается создать второй Тип события с тем же публичным ID.

Ожидаемый результат: серверная ошибка показана в интерфейсе, второй Тип события
не создаётся.

### TC-E2E-04 — Владелец удаляет Тип события без Бронирований

1. Владелец нажимает «Удалить» у Типа события.
2. Отменяет подтверждение и убеждается, что Тип события остался.
3. Повторяет удаление и подтверждает его.

Ожидаемый результат: после подтверждения Тип события исчезает из списка.

## Доступность

### TC-E2E-05 — Владелец сохраняет недельную Доступность

1. Владелец открывает Доступность.
2. Включает один день недели, добавляет интервал и задаёт его границы.
3. Сохраняет форму и перезагружает страницу.

Ожидаемый результат: Часовой пояс календаря, включённый день и интервал
сохраняются и отображаются после перезагрузки.

### TC-E2E-06 — Владелец создаёт и удаляет Исключение доступности

1. Владелец задаёт дату, режим «Заменить интервалами» и особые часы.
2. Сохраняет Исключение доступности.
3. Отменяет удаление, затем повторяет и подтверждает его.

Ожидаемый результат: Исключение появляется в списке, переживает отмену удаления
и исчезает только после подтверждения.

## Бронирование

### TC-E2E-07 — Гость проходит полный сценарий Бронирования

1. Гость открывает публичный список Типов событий.
2. Выбирает Тип события, Часовой пояс гостя и свободный Слот.
3. Вводит имя и email и подтверждает Бронирование.

Ожидаемый результат: браузер показывает подтверждение с Типом события, датой,
временем, длительностью и Часовым поясом гостя; имя и email отсутствуют в URL.

### TC-E2E-08 — Занятый Слот больше не предлагается

1. После Бронирования Гость возвращается в календарь того же Типа события.
2. Открывает ту же дату и Часовой пояс гостя.

Ожидаемый результат: забронированный Слот отсутствует среди доступных.

### TC-E2E-09 — Конкурентная запись другого Типа события отклоняется

1. Два Гостя в отдельных страницах браузера выбирают один стартовый Слот у
   разных Типов событий.
2. Первый Гость подтверждает Бронирование.
3. Второй Гость подтверждает уже выбранный Слот.

Ожидаемый результат: первый Гость видит подтверждение; второй видит ошибку
конфликта, занятый Слот исчезает, а после выбора следующего Слота введённые
контакты остаются заполненными.

### TC-E2E-10 — Владелец видит Бронирование

1. После успешного Бронирования Владелец открывает общий список предстоящих
   Бронирований.

Ожидаемый результат: показаны snapshot названия и длительности Типа события,
начало, окончание, имя и email Гостя.

### TC-E2E-11 — Подтверждение нельзя открыть напрямую

1. Гость открывает URL подтверждения без состояния завершённого Бронирования.

Ожидаемый результат: персональные данные не восстанавливаются из URL; показано
«Подтверждение недоступно» и переход к выбору Типа события.

## Кабинет Владельца календаря

### TC-E2E-12 — Владелец открывает кабинет и переходит во все разделы

1. Владелец открывает главную страницу и переходит в свой кабинет.
2. Последовательно открывает Типы событий, Доступность и Бронирования.

Ожидаемый результат: кабинет содержит понятные переходы, каждый из которых
открывает соответствующий раздел управления.

## Дополнительные свойства прогона

- TC-E2E-07 выполняется на мобильном viewport и управляет выбором Слота с
  клавиатуры.
- Все проверки используют ролевые и текстовые локаторы доступного интерфейса,
  а не CSS-классы реализации.
- Playwright сохраняет trace при падении, а GitHub Actions публикует отчёт и
  trace как артефакт.
